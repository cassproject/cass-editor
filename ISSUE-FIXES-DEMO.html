#1427  Progression model: ceasn:publisher should be an array

Cause: conceptArrays() excluded ceasn:publisher from scalar→array coercion, so progression models and concept schemes emitted a bare string when a single publisher was present. The framework export path (stripNonCe) had no such exclusion.

Test case

Save a Progression Model with exactly one publisher, then GET /api/ceasn/<guid> from a live local CASS server. Only the server branch differs between the two runs.

Before — server on 1.7
ceasn:publisher = "https://credentialengineregistry.org
                    /resources/ce-1111…"

               ← bare string
After — server on issue-1427-1.7
ceasn:publisher = ["https://credentialengineregistry.org
                     /resources/ce-1111…"]

               ← array, matches framework export

#1421  Progression Model export shows a w3 label for skos:notation

Cause: cass2ceasnProgressions.json declared skos:notation without @type, so values expand as untyped literals. The credreg target context types the term xsd:string, so JSON-LD term selection can't match it — and JSON-LD 1.1 forbids the compact-IRI fallback when a term of that name exists. The full IRI is emitted verbatim. cass2ceasnConcepts.json already had the @type, which is why concepts were unaffected.

Test case A — live export (reproduces the bug)

Same live server and progression model as #1427, with skos:notation = "TK":

notation key = "http://www.w3.org/2004/02/skos/core#notation"   ← the bug, reproduced live

Test case B — compaction harness

Mirrors the server's jsonLdCompact call exactly: same jsonld@9, same live credreg target context; only the progression context differs between runs.

    = "TK"

Bonus defect fixed in the same file: the asn prefix was lowercase (purl.org/asn/…) while credreg and every other CaSS context use uppercase purl.org/ASN/…. That leaked full IRIs for asn:* terms through the identical mechanism — visible in the @type row above.
Why the live AFTER is still pending: the CASS server fetches this context over the network from schema.cassproject.org at export time. Until the schema site is deployed from issue-1421, a live export still shows the old key — which is exactly what the local server shows today. One deploy fixes 1.6 and 1.7 at once.

#1425  Require a publisher for Concept Scheme and Progression Model

Two halves, per the issue comment ("for Manual editor and import").

Import half — driven through the real CTDL-ASN importer

Editor half

"isRequired": "true" added to the Publisher descriptor in ctdlAsnConceptSchemeProfile and ctdlAsnProgressionModelProfile. This rides the same mechanism that already enforces description and publicationStatusType on those very profiles: Publisher renders with an asterisk, and Done editing refuses to close with "Publisher is required. Please enter a value." Creating a new object is unaffected — the creation flows never consult profiles.

Not yet demonstrated in the UI. This needs a click-through against a logged-in editor session; see "What's left" below.

#1423  Validate URLs (registry URL vs CTID) on CSV import

Reference fields may hold a CTID or a URL. Previously any value starting with http passed through the importer completely unchecked. Now non-CTID values must be URLs whose origin matches the environment's newObjectEndpoint, and a mismatch blocks the import. Active only when ceasnDataFields=true.

Test case — real framework CSV through the real importer

ceasn:creator = https://example.com/not-the-registry, environment endpoint …/resources/:

Before — no urlRules

After — urlRules active

Control — identical CSV with a registry-origin URL instead: VALIDATION PASSED (import proceeded).
